Architecture Brief · Companion · Knowledge Plane

The Knowledge Plane, in detail

Ingestion, indexing, and deterministic retrieval over code, Jira, Confluence, meetings, and Obsidian — with no locally hosted models.

2026-07-27 · Draft 4.1 · Postgres becomes the search engine (FTS + pgvector); OpenSearch demoted to a deferred scale option — the whole stack now runs locally without Docker

Design thesis

Retrieval is a fast, deterministic function, not an agent. Every source normalizes to one canonical document model; lexical and structural search do most of the work; embeddings come from an API through your gateway, once per content revision; rank fusion is arithmetic you own. The only LLM calls are one bounded summary per meeting and opt-in synthesis at the edge.

Deployment realityYour ELK is a hosted logging cluster for microservices — it is a data source, not a home. Logs stay where they are and are queried live via a fetch_logs MCP tool; they are never re-indexed into the knowledge plane (volume, retention, and cost all say no). The knowledge plane ships as containers on the same hosted Kubernetes your services run on: connectors as CronJobs, the retrieval service as a Deployment, Zoekt as a StatefulSet with a PVC, Postgres via operator or a managed offering, and Postgres carrying catalog, link graph, and search in one store (OpenSearch enters only if scale later demands a dedicated cluster). The same stack runs fully local for development — macOS (brew), Linux (apt), Windows via WSL2 — with no Docker: brew/apt processes, connectors as CLI runs, MCP over stdio. Native Windows is explicitly not a support target; WSL2 is the Windows path (the two components with Windows friction, pg_search and Zoekt, are POSIX-clean under WSL).

Constraint honoredNo local model hosting. Embeddings via MaaS API through the LiteLLM gateway (batch, ~$0.01–0.02 per million tokens). No local cross-encoder reranker — v1 ships without reranking; an API reranker is added only if the eval suite proves the gap. ELSER is out: it runs models on Elasticsearch ML nodes, which is self-hosted model serving by another name — and needs Platinum anyway.

04Ingestion — the per-source fine print

The pipeline shape is identical for every source (connector → raw blob → normalize → chunk → hash gate → write). What differs is where each source will hurt you:

  • Confluence. Incremental CQL on lastModified. The trap is conversion: storage format → markdown is lossy — macros, includes, and layout tables can turn into garbage chunks that poison BM25 and embeddings alike. Expand common macros, drop unrenderable ones explicitly, and keep a conversion-quality sample in the eval set. Honor page-level restrictions, not just space permissions — pages restricted tighter than their space are the classic enterprise-search leak.
  • Jira. Issue = parent doc; description and comment threads as child chunks; status/labels/components as filterable metadata, not body text. Regex-extract issue keys everywhere (commits, PRs, pages) into the link graph.
  • Code. Never in Elasticsearch. Zoekt for text, SCIP for symbols, git metadata (CODEOWNERS, blame recency, commit→ticket links) into the catalog. Semantic code embeddings deferred until lexical+symbol hit-rate data argues for them.
  • Transcripts. Allow-listed meeting types only — engineering reviews and incident calls in, HR and legal-adjacent meetings never ingested. One small-model MaaS pass per meeting produces a structured summary (decisions, actions, topics) stored as quality_tier: generated; the raw transcript indexes at the lowest tier with a retention clock.
  • Obsidian. Cheapest connector: git-synced markdown, chunk by heading, [[wikilinks]] feed the link graph. Everything here is quality_tier: curated — the top ranking prior — because a human approved it. Workflows write proposals back as git PRs; humans merge; the corpus compounds.

05The query path

No LLM interprets queries. A rule router classifies them — developer queries are heavily patterned, so rules cover the overwhelming majority:

"PAY-981"                        → catalog lookup + expand()        0 tokens, a join
"RetryHandler.java:142" / path   → Zoekt file/path search
handleRetry-shaped token         → symbol DB
quoted string / error message    → Zoekt + ES phrase, exact match
natural language (the rest)      → search cluster: BM25 ∥ kNN → RRF

Fusion is Reciprocal Rank Fusion computed in the retrieval service — fixed k=60, per-arm weights in config, ties broken on doc id. Rank modifiers are closed-form and versioned in git: exponential recency decay and the quality-tier prior (curated > authored > generated > raw). Because every stage is code, the whole path is regression-testable: a golden set of ~50 real queries per team runs recall@10 in CI on every chunker, ranking, or model change.

Results are two-phase by design: search_* returns IDs, titles, and snippets — compact enough for an agent to scan for a few hundred tokens — and only get_doc returns full content. This is the single biggest token-cost lever in the whole platform.

06Heavy critique — where this design is weakest

What a hostile reviewer should say about this design, with the honest response to each:

ACL fidelity is the hardest promise on this page

High

Group-sync lag creates a leak window when someone loses access; Confluence page-level restrictions are easy to miss; fail-closed over-filtering silently degrades results and erodes trust in the other direction. This is the risk that turns the project into an incident.

ResponsePermission sync every 15 minutes, not nightly; page-level restriction checks in the Confluence normalizer; a red-team eval — restricted docs planted per tenant, CI asserts they never surface for unauthorized identities. Ship this before wide rollout.

“Deterministic” is overstated for the vector arm

High

HNSW is approximate: recall varies with segment merges and replica state, so kNN results are stable, not bit-identical. Claiming full determinism invites embarrassment the first time a golden-set run flickers.

ResponseReframe the guarantee: the lexical and structural paths (most traffic, via the router) are strictly deterministic; the hybrid path is bounded-variance, with BM25 as the primary arm and kNN as recall assist. Small tenants can use exact kNN. Golden-set assertions on the hybrid path use recall@10 thresholds, not exact orderings.

API embeddings put a third party on the critical path

Med

Providers deprecate embedding models; a forced migration means a full re-embed and eval re-baseline, and you cannot A/B a replacement locally. Ingest also now depends on MaaS availability.

ResponseCheap in practice: 1M chunks ≈ 500M tokens ≈ $5–10 at batch rates for a full re-embed — the cost is the eval re-baseline, not the compute. Store model id with every vector, keep raw blobs for replay, and queue-buffer ingest so MaaS outages delay freshness rather than lose data. This is a manageable tax for honoring the no-local-models constraint.

Confluence-to-markdown conversion quality decides doc retrieval

Med

Enterprise wikis are macro soup. If 20% of pages normalize into mangled chunks, hybrid search degrades in ways dashboards will not show — users just quietly stop trusting it.

ResponseTreat the normalizer as a first-class component with its own test corpus: sample pages per space, human-graded conversion checks, and an explicit “could not render” marker that excludes a chunk rather than indexing noise.

Symbol precision is uneven and will be blamed on the platform

Med

SCIP indexers are excellent for some languages, absent for others; tree-sitter fallback is single-file approximation, not real cross-file resolution. Users experience this as “find-references is wrong.”

ResponseLabel fidelity per language in tool responses (precision: full | approximate) so agents and humans can weigh results; prioritize SCIP coverage for the org’s top languages; revisit Sourcegraph Enterprise if symbol demand outgrows this.

Freshness gap during incidents

Med

Webhooks drop; the nightly reconcile means content can be stale exactly when an incident-triage workflow needs the page edited an hour ago.

ResponseAdd a pull-through path: get_doc(id, fresh=true) fetches live from the source API, returns it, and re-indexes as a side effect. Deterministic, bounded, and only paid for on demand.

Curation rot: the Obsidian tier can rank stale truths first

Med

A curated note from 2024 outranking this month’s Confluence page is the failure mode of quality priors — yesterday’s architecture served as today’s answer.

ResponseRecency decay applies to curated content too, just with a gentler half-life; vault notes carry a reviewed: date in frontmatter, and a monthly workflow files PRs against notes past their review window.

The real long-term cost is connector maintenance, not compute

High

Five connectors × API changes, auth rotations, and edge cases is the unglamorous work that kills internal platforms — the search infra will outlive the enthusiasm for feeding it.

ResponseConnectors are owned, on-call-adjacent software with contract tests against each source API and staleness alarms per source (“Confluence cursor hasn’t advanced in 24h” pages someone). Budget it into headcount honestly or the plane silently rots.

Buy-vs-build: you are building Glean-lite — say so out loud

Med

Glean’s architecture — hybrid retrieval over a permissions-aware knowledge graph, ACLs enforced at query time — is exactly this design, productized with 100+ connectors. And Atlassian now bundles Rovo free into Cloud Premium/Enterprise plans.

ResponseThe build case rests on three legs: the org is on Data Center (Bitbucket + Bamboo), where Rovo doesn’t reach; Rovo and Glean are human-search products with weak MCP/agent extensibility, while this plane is agent-first; and determinism + cost control are design goals no vendor sells. If the org migrates to Atlassian Cloud or Glean lands enterprise MCP access, re-run this decision — the connectors and catalog survive either way.

07What changed from Draft 1

  • Embeddings moved from local bge/gte serving to MaaS batch APIs through the gateway — the no-local-models constraint costs single-digit dollars per full corpus embed at current batch rates.
  • RRF moved from “Elasticsearch does it natively” to in-service fusion — the native RRF retriever is Enterprise-licensed; owning the ~20 lines is cheaper, deterministic, and portable to OpenSearch if licensing ever forces the move.
  • Local cross-encoder reranking dropped; replaced by “nothing until evals prove the gap, then an API reranker.”
  • Determinism claim downgraded honestly: strict on lexical/structural paths, bounded-variance on the vector arm.
  • OpenSearch demoted from default to deferred scale option (4.1). At this corpus size, Postgres FTS + pgvector carries hybrid search inside the same instance as the catalog — one stateful service instead of two, exact vector scan instead of approximate ANN, and the whole stack runs locally via Homebrew with no Docker. OpenSearch returns only if chunk count or relevance tooling outgrows SQL; because the engine is just an executor behind the retrieval service, the swap is invisible to every agent.
  • Search fully decoupled from the logging ELK (2.1). Your ELK is a hosted logging cluster for production microservices — not yours to extend, and the wrong place for knowledge indexes even if it were (a noisy log day would degrade retrieval; retrieval load would degrade incident response). Its role narrows to a live query target behind fetch_logs.

08Implementation phases

Sized for one builder plus AI agents, part-time alongside other work. Each phase is independently valuable — if investment stops after any phase, what shipped still pays for itself. Weeks are effort estimates, not calendar promises.

Operating model: local-first, prove, then promote. Phases 0–1 run entirely on a laptop (brew/apt Postgres, ingest as CLI runs, MCP over stdio, personal credentials only — ACL by construction, since you can only ingest what you can read). Promotion to kube happens per component, each with its own gate:

OrderPromotesGateWhat changes
P1Postgres → operator/managed on kubeLocal proof complete (see criteria below)A connection string. Data re-ingested from sources, not migrated — the connectors are the recovery path by design
P2retrieval-svc → Deployment, HTTP/streamable MCP + token-issuerACL red-team suite green + per-user MCP auth spike verified in Amp/Copilotstdio → HTTP transport; implicit identity → per-user short-lived tokens; audit log becomes load-bearing
P3Connectors → CronJobs + webhook-receiverP2 live; service accounts vault-managedPersonal credentials → service accounts — this switch happens only on kube, never on laptops; webhooks + reconcile replace manual CLI runs
P4Zoekt · embeddings · transcriptsTheir existing evidence gates (v0 failure data, eval gap)Born on kube — never local obligations

“Proven” means, concretely: the expand() demo works on real org data; a recall@10 baseline exists over 20–30 real golden queries; two weeks of daily self-use show agents reaching for the MCP tools instead of exploring (visible in your own Amp threads); p95 tool latency under 500 ms locally. Because every component is 12-factor and the CI builds the images, each promotion is configuration and supervision — not a rewrite; the laptop profile survives forever as the development environment.

Two sequencing rules the phases encode: nothing rolls out beyond the pilot before the ACL gate is green (phase 2 is the gate, not a feature), and the two expensive optional components — Zoekt and embeddings — each require data from the previous phase to justify their existence. The cheapest infrastructure is the component you measured your way out of building.
