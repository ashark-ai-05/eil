01Sourceswhat you can already read

Only the spaces you name, selected by CQL — pages and their attachments, on your credentials.

Projects scoped by JQL — issues, descriptions and comment threads become docs.

Clone, walk, filter by glob — binaries and oversize files never enter the index.

Local markdown, runbooks and log archives — the long tail that never had a home.

Your credentials. You can only index what you could already read. Ingest adapters: confluence · jira · obsidian · repo.

02Ingestonly what changed

Each connector resumes from a saved cursor — a re-sync moves the mark, it doesn't re-read the world.

Re-indexing a repo is a diff, not a re-read. Deletions leave a tombstone so results can't outlive the file.

Overlapping line-windows, so an answer that straddles a boundary is still found — and still cites a line range.

Only what changed. Hash-gated, incremental, tombstoned.

03Indexone Postgres, no extension

Exact terms, identifiers, error strings — the things an embedding blurs. Plain Postgres full-text.

Meaning, embedded locally and stored unit-normalized as float4[] — so cosine is a plain dot product Postgres can compute itself, and only the top matches ever leave the database. No extension to install anywhere.

Visibility lives on the doc, not the query. An unstamped doc is owner-only — so a bug fails closed.

One Postgres. PGlite · embedded PG · system PG · org DSN — no extension, no Docker.

06Agentsthe consumers

Connected over MCP — pulls ranked, ACL-filtered context before it answers.

Same two-phase contract — grep the org the way it greps the repo.

The contract is the protocol, not the vendor. Anything that speaks MCP gets the same guarantees.

What they ask — and what returns nothing — becomes the signal below.

05ServeMCP · two-phase

Two calls, deterministic. Search returns ids and snippets; the agent fetches only the ones it wants — zero tokens spent searching.

search_docs · get_doc · refresh_doc · expand · search_code · fetch_logs

A small, closed surface — nothing that writes, nothing that reasons.

Every tool call and every model call lands as a logged row — who asked, what matched, what came back.

No LLM in the hot loop. Retrieval is a query, not a completion.

04Searchtwo arms, fused

Ranks by term match. Wins on exact — a stack trace, a flag name, a ticket key.

Ranks by meaning. Wins when the asker doesn't know the vocabulary.

Best-effort — if the model is unavailable the arm drops and search degrades to FTS-only rather than failing.

Reciprocal-rank fusion — one list from two rankings, with no score normalisation to tune and no LLM in the hot loop.

The final sort: source tier, then freshness — and the ACL filter that decides what you were ever allowed to see.

Deterministic. Same query, same corpus, same order — every time.

Metrics are SQL views over the facts — the vw_* views are the definitions, not a dashboard's interpretation of them.

10 views — vw_tool_calls · vw_zero_results · vw_llm_calls · vw_connector_health · vw_eval_trend · vw_two_phase · vw_spend_daily · vw_cost_per_run · vw_tool_latency · vw_arm_mix

Recall trend and adoption decide what gets indexed or built next — the arrow that runs back over the top into Ingest.
